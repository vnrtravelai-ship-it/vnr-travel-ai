# Purpose

This document defines the standard structure of the **docs/** directory.

All future documentation must follow this structure.

Its goals are:

* Keep documentation organized
* Eliminate duplicate documents
* Make documents easy to locate
* Separate permanent knowledge from temporary records
* Support long-term maintenance

---

# Folder Description

## architecture/

System architecture documentation.

Contains:

```text
architecture/

BACKEND_STRUCTURE.md

CODING_RULES.md

DEPENDENCY_RULES.md
```

Purpose

* Backend design
* Module boundaries
* Coding conventions
* Dependency policies

---

## planning/

Planning Engine documentation.

Contains

```text
planning/

PLANNER_PIPELINE.md

PLANNING_ENGINE.md

PLANNING_ARCHITECTURE.md

KNOWLEDGE_MODEL.md

RAILWAY_KNOWLEDGE_MODEL.md

models/

PLANNING_MODELS.md

PLANNING_CONTEXT.md
```

Purpose

Describe every planning component.

---

## adr/

Architecture Decision Records.

Example

```text
adr/

ADR-001

Planning Engine

ADR-002

Knowledge Repository

ADR-003

Scheduler

ADR-004

AI Provider

ADR-005

Dependency Injection
```

Purpose

Record major architecture decisions.

ADR files are immutable after approval.

---

## sprints/

Sprint history.

Example

```text
sprints/

SPRINT-3.8.md

SPRINT-3.8.5.md

SPRINT-3.8.6.md
```

Purpose

Maintain complete development history.

Each sprint records

* objectives
* completed work
* issues
* next sprint

---

## archive/

Historical documents.

Structure

```text
archive/

audit/

refactor/

templates/

2026/
```

Purpose

Keep old documents without polluting active documentation.

Archive documents are read-only.

---

## api/

Generated API documentation.

Generated by

TypeDoc

Policy

* Never edit manually.
* Can always be regenerated.
* Should normally be excluded from Git.
